# Phase 2.1: Context & Requirements

## Overview
Phase 2.1 lays the groundwork for "The Swarm Orchestrator" epic by allowing the Jules Edge worker to act as a routing management proxy. Rather than doing the work itself, Jules can parse delegation commands and tag GitHub issues, which conceptually bridges the gap back down to the local `overseer.py` pulse running on the Mac.

## Current Behavior
The proxy only understands explicit commands pointing downward to the Jules API (e.g. `/ship`, `/review`).

## Goal
Detect when a user comments `@jules /delegate [agent-name]`.
Once detected:
1. Block execution to the actual Jules API (we don't want the core LLM doing the work if it's delegated).
2. Call the GitHub API to append a label to the issue formatted exactly as: `agent:[agent-name]` (e.g. `agent:frontend-specialist`).
3. Return a `202 Accepted` status acknowledging delegation.

This label allows the existing local infrastructure (`Mission-control/overseer.py`) to scrape the issue naturally on its next 10-minute pulse and dynamically route the code assignment directly into the designated local agent loop.
