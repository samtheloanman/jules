# Plan 1.0-01: Cloudflare Worker Webhook Receiver

<objective>
Implement the Cloudflare worker inside the `proxy` directory to act as the ingest layer for GitHub webhooks. It natively listens for `pull_request` payloads and verifies the signature using the Crypto API.
</objective>

<tasks>
<task>
  <description>Create the worker endpoint</description>
  <read_first>
    - proxy/wrangler.toml
  </read_first>
  <action>
    Export a default `fetch` handler in `proxy/src/index.ts` that listens for POST requests.
    Parse the `x-hub-signature-256` header and validate the payload using Web Crypto against a `GITHUB_WEBHOOK_SECRET` environment variable.
    Return 200 OK only if the signature is valid.
  </action>
  <acceptance_criteria>
    - `proxy/src/index.ts` contains `async fetch(request`
    - `proxy/src/index.ts` contains signature verification logic
  </acceptance_criteria>
</task>

<task>
  <description>Implement Label Detection and Dispatch</description>
  <read_first>
    - proxy/src/index.ts
  </read_first>
  <action>
    Extract the PR labels from the JSON payload. Check for `jules:review`, `jules:test`, or `jules:doc`.
    If applicable, emit a backend `fetch()` request to the `JULES_API_URL` passing the cloned payload data, ensuring that we asynchronously dispatch without blocking webhook resolution via `ctx.waitUntil(...)`.
  </action>
  <acceptance_criteria>
    - `proxy/src/index.ts` contains `ctx.waitUntil`
    - Logic explicitly searches `labels` for the required tags
  </acceptance_criteria>
</task>
</tasks>

<must_haves>
- Uses Web Crypto API for zero-dependency signature checking.
</must_haves>
