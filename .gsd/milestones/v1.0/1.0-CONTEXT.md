# Domain
Wiring up the Jules REST API for autonomous PR processing and configuring native internal scheduled tasks.

# Decisions

## 1. Webhook Hosting (Least Expensive)
**Decision**: Cloudflare Workers.
**Rationale**: Cloudflare Workers offers a very generous free tier (100k requests/day), runs on the edge, and is extremely inexpensive/free for webhook routing. It is the best choice for routing GitHub webhooks to the Jules API.

## 2. Trigger Logic (Jules Strengths)
**Decision**: Filter PRs based on what Jules excels at (Bug fixing, Test Generation, Documentation, and Linting). 
**Rationale**: We will trigger the Jules API only when a PR is labeled with `jules:review`, `jules:test`, or `jules:doc`, ensuring we only consume API quota for tasks Jules is optimal for.

## 3. State Management (Robust & Simple)
**Decision**: GitHub Check Runs / Commit Statuses.
**Rationale**: Instead of a complex database, the Cloudflare Worker will immediately create a GitHub Check Run (e.g., `jules-review: pending`) when it processes a PR. If the hook fires again, it checks the commit status—if it's already pending/completed, it ignores it.

## 4. Scheduled Tasks Scope
**Decision**: Routine codebase maintenance.
**Rationale**: Jules natively excels at "routine codebase maintenance, monitoring, or updates." We will configure the Jules UI to run scheduled sweeps that specifically invoke `checklist.py` and our test suites every night.

# Specifics & Deferred
- Ensure `AGENTS.md` explicitly lists out the GSD checking steps so Jules can read them directly.
- The Cloudflare worker will act as a thin proxy: `GitHub Webhook -> Cloudflare Worker -> Jules REST API`.
