# Phase 3.0 Context: Autonomous Multi-Agent Dispatch (GSD-Autonomous)

## Objective
Completely automate task discovery and assignment out of `overseer.py` into GitHub Issues. This establishes a fully autonomous, hands-free orchestration loop where Jules (via `jules.googleapis.com`), Claude, and Antigravity recursively pick up, execute, and sync tasks back to the central queue.

## Key Requirements from ROADMAP
1. **Auto-Dispatch Pulse:** Update `overseer.py` (located in `Mission-control`) to auto-approve tasks via a background scheduling script (`auto_dispatch.py`) acting as the `gsd-autonomous` pulse.
2. **Label Alignment:** Ensure `GitHubDispatcher` issues labels and body tags (like `@jules`, `jules:task`) precisely guarantee webhook triggers to the Jules Edge worker deployed in Phase 2.0.
3. **Recursive Loop:** Once Jules completes an issue (and generates a PR or commit), the subsequent `overseer` pulse must accurately detect completion via state files or repository changes.

## Baseline Research Answers
Resolving open questions from `research/questions.md`:

**Jules PR Hook Requirements:**
*   **Payload parameters:** As observed in `proxy/src/index.ts`, the `v1alpha/sessions` endpoint minimally expects `projectUrl` (the repository URL), `context` (e.g., event string or PR number), and `initialMessage` (the prompt).
*   **Rate Limits & Timeouts:** Jules sessions usually run asynchronously on the serverless endpoint. Since the Edge Worker makes a Fire-and-Forget `ctx.waitUntil(triggerJulesAPI(...))` call, the Cloudflare worker avoids waiting for the potentially multi-minute timeout of the Jules analysis loop. The GitHub webhook has a 10-second timeout limit, which is already safely mitigated by `ctx.waitUntil`.
