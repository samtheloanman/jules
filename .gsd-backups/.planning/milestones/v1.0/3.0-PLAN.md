# Phase 3.0 Plan: Autonomous Multi-Agent Dispatch

This phase closes the loop between the passive project scanner (`overseer.py`) and the active multi-agent webhook we built in Phase 2.0. By putting `overseer` into an autonomous dispatch loop, it will auto-detect stalled tasks and generate GitHub Issues which immediately ping Jules to begin executing them. 

## User Review Required

> [!IMPORTANT]
> **Issue Deduplication Strategy:** 
> Right now, `overseer.py` generates deterministic hashes for tasks based on their `project` and `task_description`. If we auto-dispatch, it takes ~5-15 mins for an AI to finish the task. If the `overseer` runs again *while* the AI is coding, it will see the task is still stalled in the Markdown files and dispatch a duplicate issue! 
> My plan fixes this by teaching `overseer.py` to refuse new proposals if the ID already exists in `history.json` and is marked `dispatched`. Is this strategy acceptable, or do you prefer a different state-tracking method?

> [!NOTE]  
> **Daemon Execution:**
> I plan to write `auto_dispatch.py` as an infinite `while True:` loop taking sleep intervals (e.g., 900 seconds / 15 minutes). You'll be able to run it via `nohup` or `tmux`.
